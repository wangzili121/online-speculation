# 111短功能测试的资源证据补采

111的第一次同步测试已经通过greedy、反馈回放、计时、控制组隔离和真实发布分片检查，但没有取得测量期间的完整worker与物理卡绑定。因此保留原始功能通过记录，并把资源证明标为缺失，不据此放行完整性能探索。

本组用同一份旧6题、初始head、计算源码和全部数值参数补跑一次短功能测试，只改变结果tag及前置依赖；不在短测试上选择性能配置。资源观察在启动阶段每4秒采集，并保留未匹配时的阶段、launcher数量及本任务NPU进程，便于定位采集缺口。原来的三卡覆盖与进程数要求保持不变，完整探索仍须有实际资源证据。

111继续遵守96GiB主机内存预检，只使用空闲卡；167正在进行的384题探索不重启、不改配置。`sync345`仅替换111的功能前置条件，原计划快照保存为`*.before-resource-supplement346`，其384题、配方及模型源码不变。功能补采及真实发布分片审核通过后，才放行111的完整探索；新确认题尚未分配。

未启动的等待任务原先只允许2、3、5、6、7，而实时空卡曾为0、1、5。现将111短测试及尚未派发的384题探索可选范围改为全部8张卡，仍只获取空闲三卡，仍保留96GiB内存预检。旧计划、旧等待进程身份及无模型/无NPU占用的退出证据保存在`../sync348/`；没有停止或重启任何NPU模型。
