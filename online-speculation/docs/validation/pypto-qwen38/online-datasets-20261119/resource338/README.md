# 三卡独立学习器的固定配方重复

每组使用三张物理 A2：TP2 执行主模型与 draft，第三张运行学习器。AR、初始固定起草、持续在线更新均保留同一组三张卡；在线计时包含反馈、反向、Adam、权重发布及流末等待。最终实际发布 head 另外做同题冻结重跑和独立 32 题留出，不用这些结果代替在线吞吐。

| 请求流 | 每次题数 | 更新参数 | 频率 | 三次顺序 / 主机 |
| --- | ---: | --- | --- | --- |
| SPoC 派生伪代码转 C++ | 256 | step128、fresh Adam、last-1、硬标签 KL、3e-5 | 前 64 步每 16 轮，之后每 64 轮；每 4 步发布 | 743 / A，744 / B，745 / A |
| GSM8K | 384 | step128、fresh Adam、last-1、TV、1e-5 | 前 256 步每 16 轮，之后每 128 轮；每 4 步发布 | 743 / B，744 / A，745 / B |

两组均为 greedy、K8、最多 7 个候选、7 个教师位置、每题最多 192 个输出 token，遇 EOS 停止，学习率前 8 步预热。数值配方沿用各数据集已冻结的版本，没有重新选择参数。GSM 的 A/B 包装不同，但 145 个模型模块与 benchmark 代码哈希完全相同；SPoC 沿用其自身的 v292 实现。模型、初始 head、源码与数据在派发前核对并绑定。

本扩展于 **2026-11-21 21:13 UTC** 登记，此时第一组三卡 SPoC 743 已开始且已有部分结果。新增重复不依据后续吞吐挑选或提前停止，负结果同样保留。这些请求来自已经分配的双卡确认题池；各次重置 head 和 Adam、改变请求顺序，**不是新的未见问题队列，也不替代双卡确认**。各对照以独立完整流顺序计时，可能受服务器负载随时间变化影响，不能只凭跨实验吞吐差异认定增加学习卡的因果收益。原 LongProc 负结果保持不变。

## 执行与采集

`registration.json` 记录登记时间、数值契约与资产哈希；`queue-*.json` 固定完整计划。A 等原 SPoC 743 完成后执行后续用例；B 先通过 C1024 功能测试，再运行 SPoC，最后运行 GSM。控制器只使用空闲卡，不停止其他用户任务，每项最多启动一次，不按性能结果扩展或重试。

`dispatch.py` 只部署实验控制与资产，不修改模型计算代码。`stage-A.json`、`stage-B.json` 保存实际派发及版本绑定。A 的首次预检因多比较了一个说明字段而退出，发生在写入和模型启动前；原错误保留，修正检查后才派发。

`watch.py` 下载原始结果、源码和日志，重新计算导出权重哈希，并检查逐请求输出、完整计时、连续更新、发布版本及实际事件。Docker 导出文件仅 root 可读时，使用不挂载 NPU、无网络的只读容器核对，不修改文件权限或模型参数。`capture_resources.py` 在执行期间绑定实际 worker、物理卡、容器与进程启动时间；`summarize.py` 只在完整证据齐备后汇总三次结果。

在本目录执行：

```bash
python3 poll.py       # 查看现有任务，不启动新模型
python3 summarize.py  # 重新核对并汇总已完成的完整记录
python3 check_release.py  # 核对已完成任务的原进程/容器退出，不停止任何任务
```

每次和合并结果都必须同时超过同条件 AR、初始固定起草 5%，才标为达标。合并吞吐使用总 token / 总时间，不能对百分比取平均。两卡与三卡分别报告。
