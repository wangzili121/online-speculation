# 三卡同步交错路径的旧输入功能检查

原三卡GSM配方有一次完整在线流仅比固定起草快约3.2%，该记录保留。接受数仍有提高，但这次在线阶段的单次draft /verify分别比固定组慢约4.6% /4.8%；另一节点的增幅更小。CPU等待时间存在差异，Docker未设置CPU限额，原因仍待验证，详见`generation-diagnostic.json`。

现有benchmark已经提供同步更新和六种顺序交错的AR /固定 /在线对照。本组先在**旧smoke6输入**上验证其与独立第三张学习卡的兼容性：TP2执行主模型及draft，逻辑设备2执行同步周期更新，使用`--interleaved --interleave-ar`。模型计算源码、基模、初始head128和共享缓存实现沿用冻结版本；这里只改变既有执行开关。

每台机器的功能检查都等待本机当前确认用例正常结束，遵守96GiB主机内存预检，只用三张空闲卡。原确认任务与数据保持原样。此门槛采用每题最多64token、TV 1e-5、短预热和每步发布，检查greedy、控制组不更新、首次反馈replay、权重版本及真实导出分片。短门槛的吞吐不用于性能资格判断。

`protocol.json`保存登记时间和边界，`queue-A.json` /`queue-B.json`给出完整命令，`launch-*.json`记录实际控制器PID与检查的源码数量。首次head预检误用了工作目录，而head实际在父目录；原只读预检失败保存在`preflight-observation-*.json`，修正后才写入计划并派发。

功能通过后，才评估旧探索语料上的同步交错执行；通过完整性能资格后再冻结配方并分配未用确认题。当前确认题上的结果继续作为原配方证据保留。

## 功能检查结果

167已通过旧6题的同步独立学习卡检查：TP2为物理0/1，学习器为2；完成8次更新、8次发布，greedy输出一致，控制组无训练，真实导出分片与实际发布版本相符。首次反馈回放的TV为0.001145、相对L2为0.002530，满足0.01的门槛。原功能测试进程已正常退出，监督器已派发旧384题的完整性能探索；短功能测试吞吐不用于资格判断。111仍在等待96GiB主机内存预检，尚未启动本组模型。
