## 文件与执行

- `registration.json`：结果完成前登记的主机、资源、固定配方和验收要求。
- `watch.py`：只在完整资格通过后调用准备和派发，观察超时不重启模型。
- `prepare.py`：再次核对题目使用情况，最后才写`frozen-recipe.json`作为准备完成标记；此步骤不启动NPU。
- `dispatch.py`：核对冻结文件，留下持久分配记录，经已有启动器只获取空闲三卡；保留96GiB主机内存门槛。
- `selfcheck.py`：CPU上的拒绝条件、参数不变和分配幂等检查，不能代表新NN性能验收。

准备完成后才出现输入文件、`queue-B.json`、冻结配方和分配清单。派发后`launch-B.json`记录真实控制器PID；各tag保存原始报告、源码、日志、真实分片哈希和资源绑定。所有三次终态证据齐备后生成`three-confirmation-audit.json`。自动流程不修改数值配方，也不自动重试失败模型。
