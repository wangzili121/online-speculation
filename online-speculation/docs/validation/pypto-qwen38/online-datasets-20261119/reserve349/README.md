# GSM8K剩余预留题的使用记录核对

原登记的1024题经过历史使用记录和head128训练/评测ID排除后，有1008题符合条件。其中384题确认集和32题留出集已经分配使用，账面剩余592题。本组继续核对这些题在三台机器上的当前使用情况，为后续新方案确认准备数据；不选择性能有利的题，也不启动模型或分配新队列。

扫描范围包括本项目OneServing目录下有`assets`的实验目录，检查已启动用例的输入和留出题、实际模型报告中的输入哈希、在途控制器及显式冻结记录已分配的队列，以及可找到的初始head128预热报告。除了精确哈希，也比较归一化文本，并检查完整题目是否包含在其他提示词中。输入缺失、报告无法解析或节点无法读取时，整体结果保持未完成，不把缺失信息解释成未见题。

## 复核命令

在`online-datasets-20261119`目录中运行，输出必须使用新的文件名，以保留此前快照：

```bash
python3 reserve349/selfcheck.py
python3 reserve349/audit_usage.py --via-A-for-C --output reserve349/new-snapshot.json
```

若只有61读取失败、111和167均成功，可用同一版本扫描代码补读61：

```bash
python3 reserve349/resume_c_via_a.py \
  --partial reserve349/new-snapshot.json \
  --output reserve349/new-completed-via-A.json
```

`selfcheck.py`在临时目录验证包裹题目、未启动输入、在途分配、未知输入和损坏报告等边界，不连接服务器，也不调用NPU。审计程序只读取实验输入和元数据，结果中保存哈希与命中信息，不保存其他输入的正文。

当前版本可直接经111读取61，并压缩SSH审计输入。已有历史快照按其记录的脚本SHA及对应Git版本解释；新增的显式分配记录即使没有活跃控制器，也会从后续可用题池中排除。
