# 初始 head 的独立对照

保持 `explore296` 的 head135 / KL / 3e-5 配方、源码、请求、顺序和生成配置不变，只将起始权重改为实际 step128，并重新创建 Adam。LongProc 30 题和 SPoC 派生 64 题分别测量两卡 TP2、rank0 共卡的 AR、固定起草、全程持续在线，以及最终发布 head 的重跑和原开发题对照。

该组在对应 TV 探索结束后才等待空闲双卡，不改正在运行的源文件，不消费新的预留确认或留出题。目标是区分起点影响，不能与不同 loss 的 TV 组混作单因素对照。

`watch_explore299.py` 只读收集完整结果，核对初始分片、冻结参数、源码、完整计时及实际发布权重。探索中同时超过两个 +5% 后，仍需另行冻结配方，再派发未使用的预留题；计划不自动触发确认。

两类数据分别收齐三种已登记配方的完整探索结果后，在同时超过两个 +5% 的配方中，按“两条完整流增益的较小值”选择。配方、源码、初始权重及请求配置冻结后再使用对应的新预留池；未达标则继续探索，不移动预留题、不截取中间窗口。`reservation-guard.json` 确认六个 case 均无自动派发确认的字段。

完整 LongProc 30 题结果：AR / 固定 / 在线为 17.288 / 17.437 / 17.885 tok/s，相对 AR +3.45%、相对固定 +2.57%，尚未达标。SPoC 的原 KL 项因前置 TV 启动失败而未启动，相同配方的恢复见 `../recovery301/`。
