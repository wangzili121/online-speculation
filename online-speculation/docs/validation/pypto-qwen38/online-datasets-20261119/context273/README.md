# 1,024 上下文的验证记录

`cpu285/` 保存 572 项检查，包括长历史末端的独立 autograd 对照。`assembly278/` 保存分页 Attention、真实形状前反向的设备二进制编译，以及 TP2 编排入口的编译结果；这些编译不占 NPU。

`device280/` 的两种页尺寸共 38 个 Attention 用例通过；同次真实权重训练在控制内存分配时 OOM，尚未执行工作区。`device286/` 保留换空卡后的成功重试：kernel 源码和真实权重输入不变，增加 6 个小形状逐节点 Torch 对照；真实 27B 的 6 组 16/32 行 logits、参数梯度逐位相同，输入只读。设备与本任务进程的只读内存观测同样保留，检查结束后释放单卡。

`service288/` 保存整模型两卡验证的计划和组件门槛：真实 27B、TP2、rank0 学习，使用旧问题构造的长输入检查反馈、greedy、行布局、更新和实际发布分片。该项仍等待两张空闲卡，不消费新题，也不作性能资格判断；先前因组件 OOM 未启动的计划及失败门槛一并保留。

`device273/`、`device275/` 保存环境信息采集阶段的失败。导出环境没有 Git 信息时，不能把“不知道版本”误判成“版本冲突”；后续改用已核对源码、原生绑定、实际 Simpler 扩展和工具链的 207 项哈希，未关闭运行时检查。`sim277/` 因主机缺少 `g++-15` 未运行模拟器，不能作数值验证证据。

`data276/` 为官方 LongProc 新题池及三台机器的执行来源审计；第一版审计误将三个计划文件当作模型结果，第二版只识别实际结果，未重跑模型。`spoc283/` 是另外准备的 SPoC 补充流，来源和结果与原 LongProc 分开。两套新确认池均未执行。审计控制脚本的本地输出目录以 `--artifacts` 指定；服务器及运行时保持记录中的固定版本。
