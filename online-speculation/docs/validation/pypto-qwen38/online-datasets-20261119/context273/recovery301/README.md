# SPoC 启动阶段的资源冲突与恢复

原 TV 流在进入生成前，目标模型的显存准入检查失败：rank0 需要约 43.0 GB，当时仅剩约 28.8 GB；选择的物理卡为 4、5，另一个用户的 uvicorn 任务在物理 4 上占用约 60 GB。该流结果为空、正常关闭，保留完整错误和源码；未产生可供选择的性能结果。后续 KL 对照因前置检查失败，没有启动模型。

恢复计划只调整空闲物理卡的候选集合，排除当时被占用的 4 号卡。TV 与后续 KL 各自的源码、head、题集、顺序、训练和生成参数全部保留，仍为两张 A2、TP2、rank0 共卡与完整成本计时。未终止其他用户任务，未降低显存准入门槛，也未重跑已完成的负收益实验。

新的 TV 结果替代原启动失败项参与同一轮配方比较；原失败不会删除或改写。新的 KL 结果仍与 head135 / KL 配方比较起点，物理卡随空闲情况选择，各流始终采用同卡同配置的 AR、固定起草与在线基线。计划不派发预留题。
