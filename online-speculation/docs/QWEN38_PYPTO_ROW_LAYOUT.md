# 双请求 draft 的紧凑计算布局

当逻辑块长为 8（anchor 加 7 个候选）时，双请求仍按每请求 32 行执行投影和共享 backbone。Attention 的可见范围已经正确限制，但矩阵核仍处理 64 行，其中大部分不会参与验证。`--compact-paired-rows` 将每请求前 16 行压紧，复用主模型已有的 M32 矩阵核处理两个请求；不修改 Attention mask、候选数、权重或主模型配置。

| 项目 | 默认布局 | 可选紧凑布局 |
| --- | --- | --- |
| 双请求矩阵计算 | 32 + 32 行，M64 | 16 + 16 行，M32 |
| 每请求有效块 | 配置的逻辑 K | 同一逻辑 K，须不超过 16 |
| 外部输入、logits 和反馈 | 每请求 32 行 | 保持每请求 32 行 |
| 单请求、K 大于 16 | 原实现 | 仍使用原实现 |

入口压紧 hidden 和 RoPE。层间投影、GDN、双向 Attention 和共享 MLP 使用紧凑行号；请求 slot、历史边界及缓存容量保持不变。层组结束时将 hidden 和最终 logits 放回原位置，未计算的尾行写零。训练采集也恢复为原来的 32 行接口，只改变无效尾行，不缩短有效监督。参数加载、优化器和发布协议不变。

代码入口：`oneserving_tp2_programs.py`；行布局：`tp2_row_layout.py`；GDN 行跨度：`tp2_gdn_convolution.py` / `tp2_gdn_rows.py`。真实模型可用 `--audit-row-layout` 对同一轮 draft 额外运行默认布局，比较有效候选的完整词表 logits。该诊断模式不参与性能结论。

## 验证

固定版本环境下，525 项 CPU 测试与真实形状的 draft / 训练入口编译通过。真实 27B、两张 A2、TP2 的默认布局回归完成八次更新，loss、梯度范数、裁剪、学习率和监督轨迹与保留版本逐值相同，最终两个发布 shard 的 SHA256 一致；greedy 与 AR 一致。

独立单卡检查覆盖压紧、恢复、第二个请求的反馈，以及非零历史下的卷积和 GDN 递推。有效行与原布局逐位一致，尾行正确清零，输入和历史状态未被修改；递推也通过独立 Torch 参考检查。组件测试第一次在测试脚本编译时因元组赋值语法退出，改为独立赋值后通过；产品源码未因此更改。更早两次完整入口编译的形状推导失败也保留在证据中。

K8 的真实 27B、两张 A2、TP2 整模型检查通过：128/128、256/128、256/256 三种历史容量组合下，有效候选的完整词表 logits 与默认布局逐位一致。八次更新轨迹和最终两个发布 shard 的 SHA256 也与默认布局一致；教师回放最大 TV / 相对 L2 为 0.001145 / 0.002530，greedy 与 AR 一致，服务正常退出。

随后启动无额外诊断的完整流计时：Pseudo2code 的 54 题分别比较同一源码的默认与紧凑布局；GSM8K 保留完整 128 题及 384 题探索。每次的固定起草与在线组同时使用同一布局，AR 保持相同主模型配置，全部更新和发布成本计入。GSM384 新版还启用了已独立验证的统计融合，与旧版比较不是单因素消融。**当前开关默认关闭；完整探索结果见下表，最终验收仍需新请求确认。** K16 整模型验证已完成八次更新，三个 128/256 容量组合的有效 logits 与原布局逐位一致；教师回放最大 TV / L2 为 0.003078 / 0.002611，greedy 与 AR 相同，发布导出核对通过。独立 Attention 检查已经在 111 的单卡完成：真实 TP2 局部形状（12 个 query head、2 个 KV head、维度 256、页长 128），历史位置 0 / 127 / 128 / 255 / 256 / 496 / 504，块长 8 / 16；覆盖 512 档、页边界和上下文末端。七项有效结果均与默认布局逐位一致，通过独立 Torch SDPA 参考；未用页及临时尾行填 NaN，历史逐字节不变。该单卡只做组件检查，已正常关闭并释放。

111 的独立准备阶段已完成：只用同样的前两题，从真实 step128 更新七次得到 step135，两份导出权重 SHA256 与 61 的准备结果相同；反馈回放、greedy 和导出核对均通过。因此两机完整 54 题对照使用相同的实际起点，而非只比较相同文件夹名。

另登记 K16 / 15 个教师位置、最多 7 个候选的完整 Pseudo2code 54 题配方。它复用相同的 16 行物理布局与同一领域准备 head，只扩大有效块和延迟监督窗口；固定与在线使用相同配置。GDN 有效递推会增加，故不能从矩阵行数相同推断总耗时不变。该配方必须先通过 K16 整模型回放检查，完整计入持续更新成本，不使用预留确认题。
