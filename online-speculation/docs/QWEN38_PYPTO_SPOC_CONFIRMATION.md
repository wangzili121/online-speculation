# SPoC 代码生成请求上的持续在线更新

本实验使用 SPoC 派生的伪代码转 C++ 请求流，按问题 ID 划分探索、确认与独立留出。它是补充代码生成实验，与原 LongProc 固定题库的结果分别统计。**三次确认已全部完成，每次及合并吞吐均比AR、同起点固定起草高5%以上。**

## 配置与测量

每次对照均用同一主机的两张 A2、TP2，学习器共用 rank0。从同一份预热的 step128 head 开始，Adam 重新初始化；只更新最后一层的全部 draft attention 参数，共104,858,112个。使用 greedy 教师标签的 KL loss（等价于这些位置的交叉熵），学习率3e-5，前8次更新 warmup；前64次每16个验证轮次更新，此后每64轮持续更新，每4次更新发布一次。

生成采用 greedy、K8、每轮最多7个候选，总上下文1024、每题最多192 token、自然EOS；执行窗口为2。AR、初始固定起草和在线组逐对请求交错测量，模型与生成参数相同。反馈、反向、Adam、发布和尾部等待都计入在线全流。

64道探索题选定配方后，冻结256道新确认题和32道独立留出题。三次分别重置 head /Adam，并用种子743、744、745重排同一确认题库；不是三个不同数据集，也没有根据确认结果调参。

每次各组均完整生成43,599 token。更新一直按计划持续到流结束，未设置更新上限；反馈、更新与上传的非重叠耗时分别占在线全流0.945% /0.992% /1.267%。读取与TP整理已包含在更新耗时内，没有重复相加。每轮平均接受候选数分别从1.306 /1.305 /1.305提高到1.814 /1.763 /1.755，所需起草和验证次数也随之减少。

第三次745在原A任务从未启动模型的前提下迁到167运行，数值配方、初始head、fresh Adam与数据顺序均保持冻结值。各次内部三组对照始终使用同一主机和同两张卡。基模、PyPTO、PTOAS及选定运行库文件逐字节核对；两台驱动及三个CANN库文件的差异单独记录，不声称整个环境字节相同，也不把跨主机结果写成只换顺序的同机实验。

## 独立学习卡的辅助对照

另用三张A2，TP2推理加独立学习器，在旧64题探索流完成全流：AR /初始固定 /持续在线为21.1963 /22.2995 /24.1508 tok/s，即在线相对AR +13.94%、相对固定+8.30%。完成107次更新、26次发布，没有跳过应执行的更新；greedy、实际发布权重、冻结重跑及事件计时审核通过。最终发布head为step232，同题冻结重跑25.1324 tok/s；这些冻结结果不计入上述在线增益。

三组均保留同样三卡资源，实际使用111的2、3、5号卡；采用分阶段计时，与双卡逐请求交错测量分开报告。它是旧探索题的辅助结果，不能当作新增双卡确认，也不能单凭跨物理卡组合的吞吐差异判断增加学习卡的收益。256题三卡辅助流仍在运行。完整记录见[三卡归档](validation/pypto-qwen38/online-datasets-20261119/aux333/)。
