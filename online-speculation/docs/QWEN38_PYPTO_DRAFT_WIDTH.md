# Qwen3.8 PyPTO 有效起草块长

Orthrus 的每个块包含一个已知 anchor 和若干 MASK。运行宽度决定 Full Attention 能看到多少个块内位置，也决定 GDN 因果递推和训练反馈的有效边界。它与每轮最多交给 verifier 多少个候选是两个参数：仅减少候选数，仍可能计算完整的 32 个位置。

## 接口

TP2 测试入口 `scripts/benchmark_qwen38_oneserving_tp2_online.py` 增加：

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `--draft-width` | 本轮 anchor 加 MASK 的逻辑宽度；同时受剩余上下文限制 | 32 |
| `--candidates` | 最多提出的 token 数，须小于逻辑宽度 | 31 |
| `--teacher-tokens` | 延迟反馈的教师位置上限，须小于逻辑宽度 | 31 |
| `--gdn-valid-rows` | GDN 只递推有效行，剩余输出行初始化为零 | 关闭 |

例如，八个位置、七个候选与七个教师位置使用 `--draft-width 8 --candidates 7 --teacher-tokens 7 --gdn-valid-rows`。主模型配置、历史缓存和 verifier 保持原有路径。参数、通信及矩阵存储仍为 32 行；head manifest 保留原训练契约，实际运行宽度单独记录在结果中，不修改权重文件。

## 执行与正确性

两条请求分别携带自己的有效宽度。分页 Attention 只读取对应历史和有效的临时块；无效 MASK 行不参与块内可见范围。训练捕获同一宽度，教师窗口最多覆盖 `width - 1` 个位置，EOS 和上下文末尾继续按实际交付长度截断。

GDN 从各请求的主模型历史状态开始，在局部状态上递推。启用有效行模式后，只循环至该请求的宽度，尾部输出清零；历史状态始终不写回。有效前缀的计算顺序不变。较小块长会改变 Full Attention 的可见内容和接受率；同一块长下跳过无效 GDN 行则要求输出、训练轨迹及发布权重保持一致，两者分别评估。

447 项 CPU 回归通过，覆盖两请求独立宽度、上下文末尾、Attention 可见范围、反馈边界及参数校验；单请求与双请求的有效行程序已通过离线编译。真实 27B 的 8/16/32 宽度服务检查和相同宽度下的 GDN 前缀等价检查仍在执行。默认保留原来的 32 行递推，未将编译通过视为实机验收。

服务检查通过后，在注册探索题上比较同两张 A2、TP2 的 AR、同起点固定起草、全程持续更新、最终已发布 head 原题冻结重跑及独立留出。反馈、训练与发布成本全部计入。块长配置先在探索集选择，预留确认题不用于调参。
