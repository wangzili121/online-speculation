# 模型验证安排

更新：2026-11-02。DSV4、GLM-5.3 暂不接训练或在线更新；Qwen3.8 继续验证现有推理和在线更新。PyPTO 只整理推理需求，不开发新 kernel。

## 本轮验证结果

Qwen 使用真实 27B 权重，两卡 TP2、eager、同步单请求；不是缩小结构的替代模型。

| 验证 | 结果 | 记录 |

| Qwen 8K 上下文 | 10 个阶段全部通过：target-only、K=2/8/17/32、末1层/末4层更新、head 重载、连续整块接受和连续拒绝。 | [阶段结果](validation/qwen38/acceptance-1102-matrix-8k.json)、[用例范围](validation/qwen38/acceptance-1102-scope-8k.json) |

| 随机采样接受分支 | 128 个种子、256 个输出位置通过频次检查；两个 rank 均实际接受过候选，同种子重跑一致。 | [独立校准](validation/qwen38/acceptance-1102-uniform-sampling.json) |

在线测试确认 head 参数发生更新、主模型权重不变、两个 rank 的更新计数和 loss 一致，重复请求的活跃内存通过检查。导出后在独立进程重载，参数哈希与导出时一致，推理及继续更新均通过。8K 的末4层测试包含 32 步固定反馈补测，loss 从 0.5044 降至 0.4929；这不是训练 head 的业务接受率或加速结论。

这些结果只覆盖表中的 TP2/eager/单请求用例。8K 矩阵未纳入已知的 JSON 数值分叉，映射 AR 的额外数值诊断未重验；图模式、动态 batch 和正式训练 head 的收益不在本轮范围。

CPU 参考测试在临时容器中移除 `torch-npu` 后运行，避免无设备时初始化 ACL；NPU 镜像没有修改。CPU 跳过的 6 项 GLM NPU demo 已单独补验，其余 CUDA 专项不记为 NPU 通过。上述有限测试容器均已删除、设备锁已释放；八卡准备与监控进程继续保留。

## 不等待八卡的工作

| 工作 | 资源 | 验收内容 |
| --- | --- | --- |
| Qwen3.8 真实 27B | 两卡，固定 BF16/TP2/eager/同步单请求 | K=2/8/17/32；长 decode、分页、上下文末端和输出边界；原生采样校准；连续接受/拒绝恢复。 |
| Qwen3.8 在线更新 | 同一两卡窗口，独立进程 | 末1层/末4层；主模型冻结、head 改变；两个 rank 的更新计数/loss；导出重载；重复请求的活跃内存。固定反馈学习检查独立于业务收益。 |
| 算子和协议回归 | CPU 或单卡 | 历史只读、数学参考、各接受位置、教师行对齐、状态布局和失败清理；不使用大模型资源等待。 |
| 八卡环境准备 | CPU、磁盘、网络 | 三台机器准备固定源码、镜像和模型；权重逐文件校验，不因存在目录就认定下载完成。 |

真实模型安排两组独立矩阵：8K 上下文覆盖多个 K 和末1层/末4层更新；32K 上下文覆盖 K=32、上下文末端、分页及更新后的请求恢复。两组都与各自进程生成的 target-only 基线对照，不跨配置借用结果。

另外用独立的均匀候选分布补测随机采样。候选 token 与传入 verifier 的概率 q 保持一致，要求每个 TP rank 实际接受过候选，并将输出频次与原生 target 的逐前缀概率比较。该测试只覆盖接受/拒绝逻辑；真实 head 的检查仍单独运行，不能把测试候选的接受率当成 head 效果。

Qwen 当前混合策略为 Full Attention 块内双向、GDN 因果递推，交付 head 必须匹配。

本轮矩阵可显式选择用例。已独立复现的 JSON 原生数值分叉保留原记录，不混入“通过”；未纳入矩阵的用例记入 `scope.json`。默认完整矩阵和严格 greedy 门槛不变。额外映射 AR 的数值诊断可以显式不运行，但原生 verifier、采样校准、缓存审计和冻结检查不因此跳过。

## 八卡窗口

GLM 以真实 45 层 W8A8、TP8 为首个八卡验收目标，按顺序运行：

```text
完整权重校验 + 同版本环境预检
  → target-only
  → 因果 KDA / 门控双向 KDA 两种 draft
  → 两种 head 导出、独立进程重载
  → 两种策略的采样功能检查
```

所有 greedy draft 必须与本轮 target-only 比较；采样功能检查不等于分布等价验收。两种策略使用各自 head，不交叉加载，也不将初始化 head 的接受率作为加速结论。

111、167、61 的资源监控保留。准备与验证进程每 3 秒检查一次；只在没有进程且剩余 HBM 符合空闲阈值时运行，不把零计算利用率当成释放。当前本项目两卡与八卡任务共用每节点文件锁，防止自身冲突；该锁和 Docker 映射都不能阻止其他用户启动任务。

61 先补 GLM 同版本权重和镜像，未完成逐文件校验前不授权模型测试。111 的已知容器访问冲突保留显式测试配置，网卡配置随预检和模型一并传递，不在代码中硬编码。

每个失败尝试保留独立输出目录，释放容器后才重试。自动尝试最多两次；每次重新执行基线及所有 head 阶段，不复用失败尝试的部分结果。连续失败停止模型任务并留下待定位状态，不无限占卡。代码或环境变更后重新预检、重新启动验证。

## 仍然独立的事项

DSV4 保留暂停基线及 C4 独立复现。恢复推理实验时，先复查原生 C4 布局问题，再做完整模型对照；本轮不启动 DSV4 在线更新。该项尚未加入 GLM 自动矩阵，不能将 GLM 通过解释为 DSV4 通过。

图模式、动态 batch、正式训练 head 的接受率、业务 goodput 与长期稳定性需要独立验收。没有匹配 head 和代表性数据时，可以证明接入和参数替换，却不能证明实际加速。
