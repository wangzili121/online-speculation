# Qwen3.8 Orthrus 在线更新性能

在线更新包含两段工作：学习卡读取推理产生的反馈，计算 draft 梯度并执行 Adam；随后将执行权重传回推理卡，切换到新版本。反向和 Adam 由 NPU 上的 PyPTO 程序执行，主机缓冲用于两张卡之间传递反馈与参数。

## 测量方法

使用真实 27B 运行产生的 8 个反馈块，分别更新最后 1 层、最后 4 层。每块采用 K32 物理缓冲、8 个有效输入位置，其中 7 行参与 KL 蒸馏。两个独立 NPU worker 执行生产代码中的反向、梯度累积、Adam、双缓冲参数传输和版本发布；完整主模型不在该计时工具中重复加载。

每组从相同 FP32 初始参数、零动量开始，预热 1 次，再计时 3 次，报告中位数。反馈每次都重新跨卡传输，不缓存固定训练批次的传输结果。计时是同步调用的主机墙钟时间，包含运行时控制开销。

## 改动

**教师反馈只传参与 loss 的行。** 教师缓冲有 32 行，但验证停止后常常仅有前几行用于监督。根据 `valid` 传输这些行即可；hidden、RoPE、Attention/GDN 历史仍完整传输，以保留既有前向和反向语义。对照测试将学习卡未传输的教师行填为 NaN，检查 loss 是否错误读取了这些位置。

**跨卡搬运复用预先登记的共享缓冲。** 原路径每次调用 `copy_from` / `copy_to`，运行时会临时创建共享内存、复制主机数据并释放缓冲。现在在两个 worker 启动前创建同一块 16 MiB 共享缓冲，通过 PyPTO 的 `inherited_host_tensors` 登记，使两端直接使用它。大张量分块搬运，反馈与参数发布都复用此缓冲；发布仍等待全部参数传输完成后再切换版本。

**长词表输入梯度使用更大的归约 tile。** LM head 的反向包含 `[32,248320] @ [248320,5120]`。保留已验证的行重排和完整词表计算，将归约 tile 从 64 调到 512，减少循环与搬运调度。独立测试对照 Torch FP32 矩阵乘再舍入至 BF16，同时检查未监督行仍为零。其他矩阵乘保持原有默认配置。

## 验证和结果

| 更新范围 | 原路径 | 仅缩减教师传输 | 共享缓冲、教师有效行与归约调优 | 更新耗时降低 |
| --- | ---: | ---: | ---: | ---: |
| last-1 | 1.631 s | 1.356 s | 0.520 s | 68.1% |
| last-4 | 5.252 s | 4.931 s | 1.504 s | 71.4% |

参数发布是原路径的主要瓶颈：last-1 从约 0.747 s 降到 0.115 s；last-4 从约 3.47 s 降到 0.50 s。整批前向与反向分别约 0.285 s、0.777 s，优化后计算本身的占比提高。

两种更新范围的 loss、最终 FP32 master、Adam 一二阶动量及执行参数都与原路径逐字节一致，包含未传教师行填 NaN 的对照；531 项 CPU 回归通过。长词表输入梯度的独立测试由 8.414 ms 降到 7.139 ms，对照 Torch 的相对 L2 误差为 0.000143，未监督行保持精确为零。

完整记录见 `validation/pypto-qwen38/update-performance-20261111/`。原始 JSON 保留每次计时、阶段耗时与各状态 SHA256。分阶段时间存在运行时波动，尤其是大参数传输；单组中位数不代表所有请求形状的性能。

更新链路的计时与生成服务的吞吐是不同指标；本测试用于定位和减少在线更新开销。生成加速仍取决于 head 的接受长度和实际更新频率。

## 复现入口

先用 `diagnose_qwen38_pypto_training.py` 产生真实反馈快照，快照包含 `manifest.json`、冻结权重、初始参数以及各反馈块的激活和教师分布。然后在配套 PyPTO 环境中运行：

```bash
python scripts/profile_qwen38_pypto_update.py \
  --capture-report /data/capture/manifest.json \
  --device 0 --learner-device 1 --shared-transfer \
  --warmup 1 --updates 3 --output update-profile.json

python scripts/profile_qwen38_pypto_linear.py \
  --capture-report /data/last1-capture/manifest.json \
  --device 0 --tiles 64 128 256 512 --repeats 9 \
  --output linear-profile.json
```

第一条命令同时对照完整教师传输与有效行传输，并检查最终参数和 Adam 状态完全一致。省略 `--shared-transfer` 可测运行时原有的暂存传输路径。第二条命令独立测量真实形状、真实冻结权重下的矩阵乘；LM 输入梯度使用真实教师与 draft 分布生成。
